# ADR-0018：明信片分享（模板 / 邮票 / 邮戳）

- 状态：已接受
- 日期：2026-09-11
- 决策人：agent + 用户（"足迹分享要做出明信片的形式，提供一定数量（暂定10款）的模板作为选择，模板可以选择图片进行创作，然后可以用编辑器，编辑明信片的内容。明信片的邮票要使用中国当年的生效邮票，并且要加上邮戳"）；标准与取舍经两轮问答逐条确认

## 背景

1. **现有分享面**：`/map` 与详情页的「分享足迹」弹层给出两样东西——① **足迹分享卡**（`share/share-card.ts`，纯 canvas 手绘 1080×1350 竖版，下载 PNG + 复制文案）；② **只读分享链接**（`POST /api/travels/share` → `/s/:token`，ADR-0012 的快照，**不含图片与坐标**）。
2. **用户诉求**：把分享做成**明信片**——多款模板可选、能用该次旅程的照片创作、能用编辑器改文字、盖上**当年**的邮票与邮戳。
3. **事实约束**：
   - 真实中国邮票票面是**中国邮政的版权作品**，本仓库没有任何邮票素材，也没有 webfont（全部系统字体栈）。
   - 图片访问需要鉴权（`getMediaBlob`），前端此前**没有任何** `drawImage`/`toBlob`/裁剪能力。
   - 富文本编辑器（TipTap，ADR-0010）是**块级排版**引擎，不适合塞进固定坐标的版式。
   - ADR-0012 刻意让公开分享面**不含图片**；若"链接打开就是明信片"就要新增公开媒体面与模板配置存储，是另一期的事。

## 决策

1. **明信片是新增形态，不替换足迹卡**：分享弹层里加「足迹卡 / 明信片」两段式切换（与地图数据范围开关同款），默认仍是足迹卡；不新开路由。
2. **一张明信片 = 单条或多条 Travel record**：单条时它既是主角也是全部内容（**不出现足迹清单**）；多条时生成**一张**明信片 + 可选清单模块。主角（`mainRecordId`）默认 = 记录集里**最新**一条（与时光轴 `newestOf` 同口径），可切换；主角决定主图、邮戳地名与日期、生肖年份。
3. **10 款模板标准**（`postcard/postcard-template.ts` 的 `POSTCARD_TEMPLATES` 是唯一事实来源）：竖版 100×148mm @300dpi = **1181×1748**，版式族（正面式 8 款 / 背面式 2 款）× 风格（复古纸 / 手账 / 极简 / 现代）；每款声明**图片张数（0–3）、足迹清单行数上限（3–5）、支持哪些模块与默认开关**。

   | # | 模板 | 版式 / 风格 | 图片 | 足迹≤ | 默认模块 |
   |---|---|---|---|---|---|
   | 1 | 经典邮政 | 正面 / 复古纸 | 1 | 3 | 地点日期·邮票·邮戳·坐标 |
   | 2 | 航空邮简 | 正面 / 复古纸 | 1 | 3 | 地点日期·邮票·邮戳 |
   | 3 | 拍立得 | 正面 / 手账 | 1 | 5 | 地点日期·邮票·邮戳 |
   | 4 | 拼贴铁盒 | 正面 / 手账 | 3 | 5 | 地点日期·邮票·邮戳·清单·图标 |
   | 5 | 图钉地图 | 正面 / 复古纸 | 2 | 4 | 地点日期·邮票·邮戳·坐标·清单 |
   | 6 | 极简墨白 | 正面 / 极简 | 1 | 3 | 地点日期·邮票·邮戳 |
   | 7 | 胶片条 | 正面 / 极简 | 2 | 3 | 地点日期·邮票·邮戳 |
   | 8 | 日出渐变 | 正面 / 现代 | 1 | 3 | 地点日期·邮票·邮戳 |
   | 9 | 背面·写信 | 背面 / 复古纸 | 1 | 4 | 地点日期·邮票·邮戳·收件人·清单 |
   | 10 | 背面·纯文 | 背面 / 极简 | 0 | 5 | 地点日期·邮票·邮戳·收件人·清单 |

   **邮票与邮戳是所有模板的既定元素、默认全开**（用户可关）：它们是用户对明信片的基本预期，不应该是“要自己去面板里打开”的选项。

4. **模块系统**：模块 = 足迹清单 / 旅行标识 / 坐标小字 / 邮票 / 邮戳 / 收件人栏（仅背面式）/ 地点日期。**模板声明能放哪些**（声明即必须真的留了落点——只有经典邮政 / 航空邮简 / 拍立得 / 拼贴铁盒 有「旅行标识」位置，其余 6 款不声明它，否则开关是空操作），用户只在支持范围内开关；换模板时**只有用户真正改过的开关**保留（与模板默认值相同的项不算用户意见，否则切到天生带清单的模板时清单反而是关的）。单条记录时面板不出现「足迹清单」开关，画布也不渲染清单。
5. **图片只取主角记录的 Travel image**（不新开上传通路）：点击选择，按点击顺序即版面顺序，最多 = 模板张数；主角记录的图片加载完成后**自动带出前 N 张**；不足时不阻止导出，版式用虚线占位提示还差几张。
6. **文字用结构化字段**（标题 / 寄语≤120 字 / 落款 / 地点 / 日期 / 收件人 / 地址 / 邮编）+ 轻量样式，**不做富文本、不做自由拖拽**：版式固定，字段才放得稳。地点与日期默认跟随主角记录（City 快照 > 地点名；日期取到达日），**只在用户没改过时**跟随换主角。
7. **邮票：自绘"当年生肖纪念票"为默认，允许上传覆盖**。
   - 票面 = 生肖主题（`zodiacOf(year)`，1900 鼠起 12 年循环，按**旅程所在年份**取）+ 面值（默认 1.20 元，可选 0.80/1.20/1.50/2.00/3.00）+ 年份 + 竖排「中国邮政」+ CSS mask 挖出的**齿孔**；虎年 / 猴年复用 Icon library 里已有的剪影（`animal-tiger` / `animal-golden-monkey`），其余生肖用生肖汉字，**不为装饰新造 12 个形状**。
   - **不内置任何真实邮票图像**（版权 + 素材依赖 + 年年换票）；想用真票的用户可上传自备图（jpeg/png/webp、≤2MB、**仅本次绘制不落库**、等比填充裁切）。
8. **邮戳**：圆形日戳 = 地名（上弧）+ 日期（下弧，日戳习惯写作 `2026.09.05`）+ 中间横条「旅行纪念」；**压在邮票一角**形成销票效果，角度由记录 id 稳定派生（-6°~-14°，像手盖的）。地名走已有数据（City 快照优先，无快照用地点名），**不为邮戳新增逆地理请求**。
9. **渲染路线：模板 = Angular 组件（HTML/CSS）+ `html-to-image` 截图导出**。理由：10 款模板本质是排版设计，HTML/CSS 写起来最快、最好改，还能直接吃现有设计 token 与 CSS mask；该库只做"DOM → 字节"这一件事（MIT、~10KB），而我们天然避开它最容易坏的两处——图片是同源 blob URL、字体是系统字体栈。
   - 预览与导出**是同一份 DOM**（同一组件、同一 1181×1748），预览的缩放挂在父容器上，导出节点始终未缩放；缩略图是同一组件 `scale(0.118)`，因此**不产生 10 张位图资产**，也不会"预览与成品不一致"。
   - 导出 PNG（无损）+ JPEG q0.92（适合社交平台，文件名后缀 `jpg`），文件名 `travel-map-postcard-{地点}-{日期}.{png|jpg}`；照片取**原图**（缩略图 320px 撑 1181px 的画布会明显发虚），因此一张图约 1–3.5MB（PNG）/ 数百 KB（JPEG）。
   - 预览的缩放挂在**包裹层**上而不是画面本身：`html-to-image` 会把计算样式里的 `transform` 一并复制到克隆上，缩放若挂在导出节点上，成品只占一角、周围留白。`.map-stage` 式的“调试属性”约定也沿用到这里：画面根节点带 `data-postcard-template`（仅调试 / E2E 断言用，样式不依赖它）。
10. **输出边界：纯本地导出**——不落库、不进 `/s/:token`、不存草稿；分享链接仍是文字快照（ADR-0012 的"不含图片"边界不变）。**不做二维码模块**（要先有公开链接 + QR 依赖，属下一期）、不做横版、不做双面两张图、不引入 webfont（手写感用系统楷体栈）。

## 影响

- 新增前端目录 `features/travel/postcard/`（模板注册表、内容模型、邮票、邮戳——这四个是纯函数 + 4 个 spec，走 vitest；导出包装层 `postcard-export.ts` 依赖 `document`/`FileReader`，只做 DOM→字节，不参与纯函数单测）与两个组件 `components/postcard-canvas`（画面，10 款版式）`components/postcard-editor`（左模板 / 中预览 / 右面板）；分享弹层只多一个形态切换。
- 新增依赖 `html-to-image`（唯一新依赖）。
- 画布的样式拆成 `postcard-canvas.scss`（公共块）+ `postcard-layouts.scss`（10 款版式）。这是本仓库**首次**用 `styleUrls` 数组：单个组件样式文件会超过 `angular.json` 的 `anyComponentStyle` 预算（4kB 警告 / 8kB 错误），拆开是两个 5–7kB 的文件、与仓库里其它超预算组件的告警同级；其余 22 个组件仍保持单数 `styleUrl`。
- `rich-text.util.ts` 新增 `plainTextSnippet()`（去标签 + 解实体 + 折叠空白，可截断），足迹卡与明信片清单共用一份实现；实体解码改为纯函数（无 DOM），使计数/摘要逻辑可在 node 环境单测。
- 已知取舍：生肖汉字票面不是"真票复刻"（刻意的）；导出一张图约 0.4–2MB（照片决定），因此同时提供 JPEG。
- 后续可接：二维码（指向分享链接）、横版朝向、明信片落库与"我的明信片"、公开链接直接渲染明信片（需要新的公开媒体方案）。

## 备选（已否决）

- **纯 canvas 手绘 10 款模板**：与 10 个版式的迭代成本不成比例；改一次版式要动绘制代码。
- **SVG 模板 + 原生导出**（零依赖）：导出最可控，但中文自动换行要自己按字符测宽、排版自由度低。
- **把 TipTap 富文本放进版式固定区域**：块级排版与固定坐标冲突，且其 DOM 难以稳定画进导出图。
- **内置真实邮票图片**：版权与素材授权问题，且要逐年扩充素材。
- **自由拖拽排版**：需要命中测试、撤销、移动端手势、越界吸附，成本高；10 款精选版式已覆盖"创作"诉求。
